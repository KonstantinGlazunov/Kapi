# Решения проекта Kapi

Обновлено: 2026-10-18. Здесь фиксируются принятые решения и действующие архитектурные ограничения. Невыполненные предложения находятся в [PROJECT_STATE.md](PROJECT_STATE.md).

## D001 — Независимая публикация через GitHub Pages

Статус: действует; существующая схема, подтверждена кодом на 2026-10-17.

Kapi публикует dist/ через `.github/workflows/pages.yml` на GitHub Pages. Основной сайт Next.js/Vercel получает эти файлы через `app/kapi/[[...path]]/route.ts` в web_designer и отдаёт их по https://erstellen-websiten.de/kapi.

Причина: обновление Kapi доступно на основном адресе без копирования файлов в основной сайт и без его пересборки.

Последствия: GitHub Pages остаётся необходимым источником файлов; его отключение требует замены этой части схемы. GPT Sites не участвует в текущей цепочке. Судьба старой публикации и миграция её пользователей требуют отдельного решения. DNS в рамках этой интеграции не меняется.

Исторический workflow: [pages.yml на базе 0c0d07e](https://github.com/KonstantinGlazunov/Kapi/blob/0c0d07ee1e3584b4ab4f0c27ce4cffb346a545ea/.github/workflows/pages.yml). В рабочей ветке его заменяет единый [test.yml](../.github/workflows/test.yml), см. D008.

Ссылки: [единый workflow](../.github/workflows/test.yml), [прокси](https://github.com/KonstantinGlazunov/web_designer/blob/main/app/kapi/%5B%5B...path%5D%5D/route.ts).

## D002 — Локальное хранение учебных данных

Статус: действует; существующее поведение.

Приложение работает без регистрации и серверного хранения учебного прогресса. История, настройки и прогресс сохраняются в браузере. Отправка результата и отзыва — отдельные действия пользователя.

Причина: простое использование без учётной записи и локальный контроль данных.

Последствия: очистка хранилища может удалить прогресс; старый домен, GitHub Pages и основной домен имеют разные хранилища. Автоматический перенос между ними отсутствует. На проверенной базе экспорт/импорт отсутствовал. В ветке `fix/pwa-safety-and-backups` реализован локальный формат резервной копии (D006); до слияния это не возможность опубликованной версии.

Ссылка: [app.js](../dist/app.js).

## D003 — Ограничения интеграции с основным сайтом

Статус: действует; существующая реализация.

Прокси не пересылает cookies, параметры запроса и заголовки посетителя на GitHub Pages; ограничивает пути, изолирует кэши worker и задаёт noindex/nofollow. Маршрут не включается в sitemap.

Причина: независимая работа приложения без передачи данных посетителя upstream и вмешательства в кэши основного сайта.

Последствия: любые изменения прокси должны сохранять эти свойства и проходить соответствующие проверки.

Ссылки: [прокси](https://github.com/KonstantinGlazunov/web_designer/blob/main/app/kapi/%5B%5B...path%5D%5D/route.ts), [тесты](https://github.com/KonstantinGlazunov/web_designer/blob/main/tests/kapi-proxy.test.mjs).

## D004 — Общая память хранится в репозитории

Статус: принято пользователем 2026-10-17.

AGENTS.md задаёт постоянные правила работы, PROJECT_STATE.md содержит состояние и передачу работы, DECISIONS.md — существенные принятые решения и их причины.

Причина: разные модели и отдельные сессии должны продолжать работу с доступным, проверяемым контекстом без зависимости от истории соседнего чата.

Последствия: документы обновляются вместе с изменениями в той же ветке/PR. Перед использованием сведения проверяются по коду и CI. Общая память становится доступна другой сессии после получения соответствующих коммитов. Эти файлы не создают автоматическую синхронизацию чатов.


## D005 — Обновление только по действию пользователя с защитой старых вкладок

Статус: реализовано в PR №2; ожидает ревью; последнее указание 2026-10-17 запрещает merge/публикацию до нового разрешения. Фактическая публикация проверяется отдельно.

Новый worker не вызывает skipWaiting при install. Кнопка на главном экране явно запрашивает активацию; активная тренировка отказывается от обновления. Новые вкладки не перезагружаются при чужом controllerchange. Перед принудительной активацией worker запрашивает подтверждение поддержки безопасного протокола у остальных вкладок; неизвестная старая вкладка блокирует активацию. Единственная старая вкладка может обновиться своей существующей кнопкой.

Причина: старый клиент безусловно перезагружается при controllerchange, поэтому одного исправления нового app.js недостаточно для перехода с v69. Закрытие всех вкладок оставляет браузеру стандартную возможность активации без принудительной перезагрузки.

Последствия: обновление при открытых старых вкладках требует их закрытия и повторного нажатия. Вручную закрытая незавершённая тренировка не восстанавливается автоматически. Проверки: [worker unit](../tests/pwa-update.test.cjs), [реальный PWA E2E](../tests/pwa-e2e.cjs).

## D006 — Версионированная локальная копия и атомарная замена данных

Статус: реализовано в PR №2; ожидает ревью; последнее указание 2026-10-17 запрещает merge/публикацию до нового разрешения.

JSON `kapi-backup` версии 1 содержит profile/settings/history и дату экспорта; максимум 2 МиБ. До подтверждения проверяются структура, данные, известная версия и опасные JSON-ключи. Импорт фиксируется одной записью `capy-count-data-v1`, после которой последующие изменения используют этот локальный контейнер. Старые отдельные ключи не удаляются. Повреждённые исходные записи не перезаписываются миграцией. Отказ localStorage включает память вкладки и видимое предупреждение.

Причина: три последовательные записи могут оставить частично восстановленное состояние при переполнении. Сервер и аккаунты для резервной копии не нужны.

Последствия: копия переносится пользователем между доменами, автоматической синхронизации нет; недоступные данные не восстанавливаются. При ошибке записи импорт не заменяет текущие данные. См. [kapi-storage.js](../dist/kapi-storage.js), [тесты](../tests/storage.test.cjs).

## D007 — Контракты текущих скриптов и основной адрес

Статус: реализовано в Kapi PR №2 и web_designer PR №17; ожидает ревью; последнее указание 2026-10-17 запрещает merge/публикацию до нового разрешения.

Основной публичный адрес и адрес отправки результата — https://erstellen-websiten.de/kapi. Контракт `kapi-runtime:v1` вычисляет область запросов и отдельное пространство кэшей из registration.scope; `kapi-public-url:v1` несёт публичный адрес в app.js. Текущие скрипты отдаются прокси без замены исходника. Сохраняется узкий проверяемый адаптер опубликованного v69; неизвестный контракт или отсутствующие legacy hooks дают 502.

Причина: независимые обновления Kapi не должны молча ломать безопасность прокси из-за переименования строки. Проверки используют настоящий checkout Kapi, не только fixture.

Последствия: смена версии контракта требует согласованной проверки в двух репозиториях. Независимая публикация, запрет пересылки данных посетителя и noindex сохраняются. Установочный URL `/kapi/index.html` внутри scope `/kapi/`; первое перенаправление с голого `/kapi` требует сети.

## D008 — Публикация артефакта того же проверенного коммита

Статус: реализовано в PR №2; ожидает ревью; последнее указание 2026-10-17 запрещает merge/публикацию до нового разрешения. Workflow действует после появления в main.

Единый test.yml заменяет прежние отдельные test.yml/pages.yml. Unit, мобильный Chromium E2E и реальный Chromium PWA обязательны; WebKit отдельно проверяет доступные онлайн-сценарии. Deploy с needs:test публикует артефакт того же запуска только на main. Playwright закреплён lockfile. Push только main и pull_request не дублируют прогон ветки PR.

Причина: отдельный мобильный job другого workflow не гарантировал блокировку публикации того же коммита.

Последствия: WebKit Playwright в доступной среде даёт internal error при офлайн-симуляции даже на минимальном baseline без Капи. В явном WebKit online-режиме офлайн отмечается UNRUN, а не pass; реальные iOS-установка и офлайн требуют проверки устройства. Уменьшение первой тренировки и новый onboarding автоподбора остаются предложениями без реализации.


## D009 — Проверка исполняемого контракта задач и независимый предел генераторов

Статус: реализовано по результату блокирующего ревью PR №2, коммит `cb9c630`; не слито.

Очередь повторения из копии проверяется как полноценная математическая задача моделью `KapiTaskSystem.isValidReviewProblem`, включая answer, операцию, формат ответа, данные представления и диапазоны визуализаций. `validateBackup` проверяет её до подтверждения, `importBackup` повторяет проверку перед единственной записью. `makeChoices` независимо отклоняет неверный ответ и ограничивает все циклы; правильный ноль в дробях не должен зависать.

Причина: JSON-структуры и числовых a/b недостаточно. Принятая запись без answer приводила к бесконечному добавлению NaN в Set. Два независимых барьера защищают также не-UI вызовы и повреждённые данные, пришедшие иным путём.

Последствия: корректные копии версии 1 всех 41 ступеней остаются совместимы, повреждённые отклоняются без записи. Данные и интерфейс не меняются ради обхода тестов. Проверки: [storage](../tests/storage.test.cjs), [bounded choices](../tests/choice-safety.test.cjs), [PWA UI](../tests/pwa-e2e.cjs).

## D012 — Подробная помощь сразу, решение с демонстрацией после второй ошибки

Принято пользователем 2026-10-18 для всех типов, не только числовой прямой. После первой ошибки сразу показывается подробный способ решения и иллюстрация, без готового результата. На рисунке последовательно убираются 3 и ещё 2 фишки; разложение 5 остаётся видно во время шагов. Используется существующий Капи, без котов. Фон с замком — отдельная текущая просьба, не часть принятой математической модели.

## D018 — Последовательная заставка со звуковыми акцентами

Принято пользователем 2026-10-18: в трёхсекундной заставке последовательно появляются знак ступени, подпись, тема и Капи; два коротких локальных звуковых акцента сопровождают знак и Капи. ## D023 — Нижний блок ввода и гибкий размер Капи

По указанию пользователя экран упражнения сначала выделяет высоту примеру, иллюстрации, подсказке и блоку ввода. Капи через flex получает оставшееся место, без отдельного фиксированного размера для простых примеров. Индивидуальные отступы блока ответов перекрыты общим отступом; нижний внутренний отступ экрана одинаков в обычном и компактном режимах. При крайнем дефиците места персонаж может уменьшиться до нулевой высоты, чтобы не обрезать учебное содержимое и управление. Реализация средствами CSS, без нового цикла измерения JavaScript.

## D024 — Язык первого запуска

Принято пользователем 2026-10-20: при отсутствии сохранённого ru/de используется первый язык navigator.languages (fallback navigator.language). Русский ru и региональные варианты дают ru; немецкий и все неподдерживаемые языки дают de. Сохранённый язык имеет безусловный приоритет, включая ранее сохранённые настройки существующих пользователей; вручную выбранный язык автоматически не меняется. Геолокация и сеть не нужны.

## D025 — Мотивация на основном персонаже

По просьбе пользователя реакции (флажок, танец и поздравления) выполняет существующий Капи на экране упражнения или результата. Отдельный мотивационный баннер с дублирующим персонажем удалён. Короткая подпись использует текущую область обратной связи; новый ответ отменяет прежнюю подпись, а переход к следующему примеру сохраняет поздравление до окончания его таймера. Приоритеты сцен, звук и начисление наград остаются в существующем контроллере. Перед коммитом пользователь получает реальные снимки для просмотра.

Дополнение D025: по просьбе пользователя убрана верхняя строка «Пример N/20»/XP на экране упражнения, чтобы отдать её высоту Капи. Полоса прогресса остаётся, итоговые числа показываются на результате. Строка статистики скрывается целиком, включая прежний значок серии; поздравления за серии теперь показывает сам Капи.
