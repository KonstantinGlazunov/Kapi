# Kapi — учимся считать с Капи

Kapi — адаптивная браузерная игра для тренировки счёта. Ребёнок решает короткие серии примеров, а Капи отвечает на результат цельной анимационной сценой: поддерживает после ошибки, отмечает исправление, празднует серии правильных ответов и завершение тренировки.

Приложение работает как статический PWA без серверной части и сборки. Интерфейс доступен на русском и немецком языках, данные хранятся только в браузере пользователя.

## Запуск

Для локального запуска нужен любой статический HTTP-сервер:

```bash
cd dist
python3 -m http.server 8080
```

Откройте `http://localhost:8080`.

Режим проверки всех реакций Капи доступен по адресу:

```text
http://localhost:8080/?kapiTest=1
```

Он не изменяет учебный прогресс и историю тренировок.

## Возможности

- тренировки на 10, 20 или 30 примеров;
- 41 этап программы: от количества предметов до степеней и корней;
- несколько представлений одного навыка на ступенях 1–14: пропущенное число, выбор выражения, десятичная рамка, числовая прямая, десятки и единицы, точки и короткие истории;
- «Lernweg / Путь обучения»: главы учебной программы с текущим шагом;
- мягкая недельная цель: 2–5 завершённых занятий без требования заходить каждый день;
- автоматический адаптивный режим и ручной выбор операций;
- очередь ошибок с повторением до двух правильных решений подряд;
- персональный темп и XP с ближайшей целью, восемью постоянными предметами и экраном «Мой Капи»;
- реакции на ответ, серии, переход уровня и итог тренировки;
- плавная покадровая анимация составного персонажа на Canvas;
- готовые CC0-звуки с генеративным резервным сигналом;
- офлайн-работа после первого открытия;
- поддержка `prefers-reduced-motion`.

## Проверка

```bash
node --test tests/*.test.cjs
```

`tests/curriculum.test.cjs` проверяет единый математический контракт Auto и Manual для ступеней 1–14, перенос и заимствование, диапазоны, варианты ответов, очередь повторения и ограничения ручных настроек. `tests/motivation.test.cjs` проверяет мотивацию, состояния анимации, звуки, финальные сцены и серии. `tests/game-experience.test.cjs` проверяет подсказки, ввод и личный темп. `tests/rewards.test.cjs` проверяет XP-пороги, миграцию, выбор предметов, сцены, звук и офлайн-ассеты.

`tests/task-variety.test.cjs` дополнительно пропускает 14 000 задач с новыми форматами через те же validators математических ступеней; проверяет подсказки, ответы, повторы и справедливость темпа. `tests/curriculum-map.test.cjs` проверяет уникальное покрытие всех 41 ступени и состояния глав.

`tests/weekly-progress.test.cjs` проверяет календарные границы и DST, миграцию, однократный учёт занятия, недельную цель и общий reveal с XP-предметом. Мобильный E2E дополнительно проверяет Home, Settings, Result и History с недельным прогрессом.

Мобильные и PWA-проверки используют Playwright **1.62.0**, закреплённый в `package-lock.json`:

```bash
npm ci
npx playwright install --with-deps chromium webkit
python3 -m http.server 8765 --bind 127.0.0.1 --directory dist
# В другом терминале из корня репозитория:
npm test
KAPI_E2E_SCREENSHOTS=artifacts/mobile npm run test:mobile
KAPI_E2E_SCREENSHOTS=artifacts/pwa npm run test:pwa
KAPI_BROWSER=webkit KAPI_WEBKIT_ONLINE=1 npm run test:pwa
```

`test:mobile` проверяет взаимодействие и раскладку в 320×568, 360×640, 390×844 и 430×932; только в этом тесте worker блокируется. `test:pwa` запускает собственный сервер и настоящий worker: первое открытие без перезагрузки, повторный запуск офлайн, manifest/scope, корень и `/kapi/`, обновление по кнопке, продолжающуюся тренировку в другой вкладке, сохранение прогресса и чужих кэшей, импорт/экспорт и отказ записи. При наличии системного Chromium задайте `KAPI_CHROME=/path/to/chromium`. WebKit проверяет обновления worker, вкладки и резервные копии онлайн; это не проверка установки на настоящем iPhone. Полная офлайн-симуляция в доступном WebKit Playwright падает с внутренней ошибкой также на минимальной странице без кода Капи; `KAPI_WEBKIT_ONLINE=1` явно исключает эти сценарии и выводит `UNRUN`. Обязательные офлайн-проверки выполняются Chromium. Минимальное воспроизведение ограничения: `node tests/helpers/webkit-offline-baseline.cjs` (ожидается ошибка в затронутой среде; не входит в успешный unit-набор). Для установленного Safari/PWA нужна отдельная проверка на устройстве.

Для проверки через настоящий обработчик соседнего Next.js-репозитория, без копирования приложения:

```bash
KAPI_PROXY_ROUTE='/workspace/web_designer/app/kapi/[[...path]]/route.ts' npm run test:pwa
# Из web_designer (KAPI_DIST — путь к настоящему checkout Kapi/dist):
KAPI_DIST=/workspace/Kapi/dist npm run test:kapi:contract
KAPI_DIST=/workspace/Kapi/dist npm run test:kapi:mounted
```

XP суммируются и не тратятся: постоянные предметы открываются при 20, 50, 90, 140, 200, 280, 380 и 500 XP. Старым профилям уже заслуженные предметы добавляются тихо. После финальной реакции тренировки новые предметы открываются одним блоком с короткой сценой `rewardReveal`; затем появляется следующая цель XP. Первый предмет в пустом слоте Капи надевает автоматически. В «Мой Капи» его можно заменить или снять. Праздничные предметы из серий временно перекрывают выбранный образ во время соответствующей сцены.

Формат задания выбирается по весам внутри разрешённой для ступени группы. Альтернативный формат не повторяется два раза подряд; исходные математические числа и операция не меняются. Первый review сохраняет формат ошибки. Личный темп обновляют только сопоставимые короткие задачи (`equation`, `missingOperand`); текстовые истории не участвуют в сигнале понижения ступени. Карта глав отражает `currentStage` и явное освоение последней ступени по прежнему критерию (не менее 9 из последних 10 правильных ответов без ожидающих повторений); XP служит только прогрессом предметов Капи.

## Публикация и обновления

Основной адрес приложения и ссылки в результате: **https://erstellen-websiten.de/kapi**. GitHub Pages (`https://konstantinglazunov.github.io/Kapi/`) остаётся независимым источником статических файлов; Next.js получает их по запросу. Копировать `dist` в основной сайт, менять DNS или выдавать общий токен не требуется.

Единый workflow `.github/workflows/test.yml` запускает unit, мобильные и Chromium/WebKit PWA-проверки. Только после их успеха job `deploy` публикует **артефакт того же checkout в том же запуске** для `main`. Для PR публикации нет. Повторного checkout в deploy и подстановки публичного URL во время публикации нет. Скриншоты доступны в CI artifact `kapi-mobile-and-pwa`. В правилах ветки рекомендуется обязательная проверка `Unit, mobile and PWA`.

После изменения любого публикуемого файла увеличьте версию `CACHE` в `dist/sw.js`: браузер сравнивает сам worker, а не все файлы приложения. Дождитесь полного кэширования при первом открытии. Следующие запуски по установленному URL `index.html` работают без сети. `/kapi` перенаправляется на `/kapi/index.html` при первом онлайн-открытии; голая ссылка без завершающего `/` вне области worker и для такого перенаправления нужна сеть. `/kapi/` и установленное приложение находятся внутри `/kapi/`.

Обновление ожидает, пока пользователь нажмёт «Доступно обновление / Update verfügbar» на главном экране. Во время тренировки нажатие запрещено. Другие вкладки не перезагружаются и могут закончить тренировку; на главном экране они применяют новую версию своей кнопкой. При первом переходе со старой версии закройте другие старые вкладки Капи: они ещё не поддерживают безопасную смену worker. Новый worker проверяет ответ остальных вкладок и не активируется принудительно поверх старой вкладки. Если все вкладки закрыты, браузер может активировать ожидающую версию к следующему запуску. Никакой гарантии сохранения незавершённого занятия после ручного закрытия вкладки нет.

Worker с контрактом `kapi-runtime:v1` сам вычисляет пути и пространство кэшей из `registration.scope`. Он не перехватывает запросы другого origin или вне своей области и читает только собственный кэш. Прокси не должен переписывать его исходник. Не меняйте версию контракта без согласованной проверки `web_designer/tests/kapi-current.test.mjs` против настоящего checkout. Для перехода основной сайт поддерживает известный опубликованный worker v69 отдельным проверяемым адаптером; неизвестные форматы возвращают 502 вместо потенциально опасного worker.

## Прогресс, резервные копии и информация для родителей

Прогресс, история, настройки, XP и предметы хранятся **только в браузере на этом устройстве**. Очистка данных браузера или удаление данных установленного приложения может удалить их. При отказе или переполнении localStorage Капи продолжает работать в памяти вкладки и показывает предупреждение. До её закрытия скачайте копию: данные в памяти не переживут закрытие.

Настройки → Общие / Allgemein → Резервная копия / Sicherung:

1. «Скачать копию» сохраняет JSON с версией формата, прогрессом, историей и настройками. Храните его в надёжном месте.
2. На другом адресе или устройстве выберите файл. До подтверждения проверяются версия, размер (до 2 МиБ), структура и содержимое.
3. Подтвердите замену текущих данных. Рекомендуется сначала скачать текущую копию. Импорт фиксируется одной записью; при ошибке записи текущие данные не заменяются.

Разные домены имеют отдельные хранилища. На основном домене Kapi использует собственные имена ключей, но браузерное хранилище разделяется с этим origin; это не отдельная база по пути. Автоматического переноса со старого адреса **нет**. Если старый адрес доступен и поддерживает экспорт, экспортируйте данные там и импортируйте на основном. В старой версии без экспорта сначала нужна доступная обновлённая версия или ручной перенос специалистом с согласия владельца; недоступные или уже удалённые данные восстановить нельзя.

Приложение не добавляет аналитику, аккаунты или серверное хранение учебных данных. Отправка результата/отзыва добровольна: родитель сам вызывает действие и выбирает приложение передачи. Скачивание и импорт копии происходят локально, файл никуда не отправляется. Копия содержит историю обучения — передавайте её только тем, кому доверяете.

## Продуктовые предложения (не реализованы)

- Первую тренировку разумно сократить до 10 заданий: ниже порог входа, быстрее первая завершённая сессия и понятный результат. Сохранить явный выбор 20/30 для следующих занятий, без смены текущих настроек существующих пользователей. Сначала проверить с несколькими семьями, хватает ли 10 задач для знакомства и начальной калибровки.
- Автоподбор стоит объяснить при первом запуске и в настройках: «Капи начинает с простого. Уверенно получается — задания постепенно усложняются. Если трудно, он предложит повторение. Скорость — не единственный показатель». Отдельно объяснить разницу между текущей ступенью и повторением старых тем. Сейчас эти изменения только предложены.
